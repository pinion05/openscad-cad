# OpenSCAD 실전 함정 카탈로그

RC 버기·1:1 버기·F1 디스플레이 모델 제작 중 실제로 발생했던 사고와 진단·해결 경로.
의심될 때마다 여기서 대조한다.

## 1. `use`는 변수를 가져오지 않는다 (최대 사고)

- 증상: 리어 휠 STL이 50mm 폭이어야 하는데 34mm짜리 이상 형상. 조립 파일의 휠
  위치 변수도 undef. **렌더만 봐서는 그럴듯하게 나와 발견이 늦었다.**
- 원인: `use <file>`은 모듈/함수만 import. 파일 최상위 `include <params.scad>`가
  없으면 그 파일 스코프의 변수 전부가 undef. undef는 치수가 0/이상값으로
  조용히 붕괴한다.
- 해결: 부품 파일·조립 파일 모두 `include <params.scad>` 직접 명시.
  빌드 스크립트는 stderr을 버리지 않고 `build_warnings.log`로 남겨
  "Ignoring unknown variable" 경고가 보이게 한다.
- 파생 규칙: 검증 스크립트의 부피/바운딩박스 리포트로 "의도 치수 ≠ 실측"을
  상시 대조한다 (bbox 이상 = 변수 붕괴 신호).

## 2. 실린더 `center=true` 누락

- 증상: 림 배럴의 내경 보어가 인보드 쪽 반만 솔리드로 막힘 → 너클·스텁액슬과
  5,400mm³ 교집합.
- 원인: `translate([0,0,-1]) cylinder(r=..., h=...)` — center가 없으면 z=-1에서
  위로만 자람. 대칭 보어 컷이었는데 한쪽만 잘렸던 것.
- 해결: `cylinder(..., center=true)` + 길이 여유. 배럴 컷은 h=barrel_len+4로
  양끝 돌출.
- 진법(진단 테크닉): ① trimesh `mesh.contains()`로 보어 내부 점 프로브
   (rtree 필요) ② 부품을 프리미티브별로 분리 익스포트해 범인 특정
   ③ 교집합 정점의 좌표값 히스토그램 — 파라미터 값(-2.5, 0, 2.5, 6...)이
   그대로 보여 어느 프리미티브인지 역추적 가능.

## 3. 캡슐(hull-sphere) 튜브 끝단

- 증상: "0.4mm 클리어런스"로 설계한 스포일러 스트럿 하단이 리어 패널에 3mm 가량 파고듦.
- 원인: `rod()` = hull of spheres. 끝점에서 od/2 만큼 더 뻗는다. 실린더 기준으로
  클리어런스를 계산하면 안전거리가 반지름만큼 부족.
- 해결: 부품 경계을 넘는 튜브는 끝점을 반지름만큼 더 띄우거나, 끝 몇 mm를
  평평한 실린더로 마감.

## 4. orient() 회전 순서

- 증상: 이 헬퍼를 쓰는 쇼크업소버 전부가 일관되게 엉뚱한 방향 → 휠·패널 대형 간섭.
- 원인: ẑ→v̂ 매핑은 Rz(φ)·Ry(θ) 순서(외부 Z, 내부 Y). Y를 밖에 두면 회전축이
  이동하지 않아 결과가 항상 XZ 평면에 갇힘.
- 해결: SKILL.md의 검증된 스니펫 사용. 방향 헬퍼는 비대칭 마커(한쪽만 큐브 붙이기)로
  렌더해 방향을 눈으로 확인하고 커밋할 것.

## 5. `-D` 오버라이드의 한계

- 시도한 것: ① 파일에서 할당된 변수를 -D로 덮지기(무효 — 파일 할당이 이김)
  ② 미할당 sentinel(`fn_override`) + `is_undef()` 삼항(루트에선 되지만
  include 실행 시점과 어긋남) ③ wrapper 파일에서 include 전 선할당
  (동작은 하나 `use`된 파일 스코프까지는 전파 안 됨).
- 결론: 전역 해상도 스위치가 필요하면 호출마다 명시적 `$fn=` 인자를 피하고
  루트 `$fn` 하나로만 통제. 안 되면 풀해상도로 익스포트하고 파일 크기로 타협
  (14만 삼각형 조립 STEP = 24MB, 수용 가능).

## 6. 음수 길이 파라미터

- 증상: `plate(60, y1-y0)`에 y1<y0 (뒤<앞 네이밍) → hull이라 에러 없이 동작하지만
  코너 계산이 뒤집혀 실제 폭이 의도보다 4mm 큼 → V브레이스와 충돌.
- 해결: 파라미터를 `yf/yr`(앞/뒤)로 명명하고 길이는 항상 양수 조합
  (`abs()`는 증상 은폐일 뿐).

## 7. 카메라/뷰 형식

- 6값 eye/center 형식 + `--projection=p` + 명시적 거리가 안정적.
- `--viewall`은 eye/center와 조합되며 방향을 예상과 다르게 재조정할 수 있고,
  gimbal 형식(translate+rot+dist 7값)은 프리셋 회전값(GUI: Top=(0,0,0),
  Front=(90,0,0), Right=(90,0,270), Diagonal=(55,0,25))과 짝이 맞음.
- 부품 단독 렌더는 `--autocenter --viewall --camera=0,0,0,60,0,30,0`로 충분.
- 투시 뷰는 착시가 심하다(측면도를 3/4뷰로 오독한 사례). 방향이 중요하면
  eye/center를 코드로 박아둘 것.

## 8. Python 라이브러리 버전/API

- trimesh: `contains()`→rtree, `split()`→scipy+networkx 필요. 없으면 그 기능에서만 죽음.
- cadquery 2.8: `importers.importStl` 제거됨. STL→STEP은 OCP 직접
  (`RWStl.ReadFile_s`, `tri.Node(i)`, `tri.Triangle(i).Get()`,
  `BRepBuilderAPI_MakePolygon/MakeFace`, `STEPControl_Writer`).
- 스크립트 작성 전 `dir(모듈)`로 실제 API 10초 확인이 문서 기억보다 빠르다.
- manifold3d `Manifold`에는 `.bounds`가 없다(`.bounding_box()`). trimesh와
  섞어 쓰는 진단 스크립트에서 bbox 프리필터를 걸 때 AttributeError로 조용히
  죽지 않게 할 것.

## 9. 운영: 공유 워크스페이스

- 세션 중 같은 디렉터리에 다른 에이전트의 병렬 산출물이 생길 수 있다.
- 내 산출물과 경로 분리(고유 접두사/하위 디렉터리) + 커밋은 화이트리스트 복사로.
  상대방 파일을 gitignore로 가리는 것보다, 레포를 새 디렉터리에 원하는 파일만
  복사해 만드는 것이 안전하다.

## 10. 미러 루프(`for s=[-1,1]`) 안의 X축 실린더·포인트 좌표

- 증상(1:1 버기): ① 좌측 허브 스터브가 차체 **안쪽**으로 뻗어 하프샤프트를
  관통(329cm³, bbox 220×60×60이 액슬 높이 중앙에 정확히 나타남) ② 좌측
  코일오버가 **아예 없고** 좌측 쇼크 타워 슬롯도 안 잘려 후드를 뚫음(50.8cm³).
- 원인: X축 실린더를 `translate([s*x0,...]) rotate([0,90,0]) cylinder(h=L)`로
  그리면 s=−1에서 시작점만 미러링될 뿐 **뻗는 방향은 항상 +X** → 좌측 부품은
  차체 중앙으로 자람. 마찬가지로 루프 안에서 축 좌표(쇼크 상하점)를 상수로
  쓰면 두 번 루프가 같은(+x) 위치에 그린다.
- 해결:
  - 실린더: `rotate([0, s*90, 0])` — 방향까지 s에 비례.
  - 점 기반 도형: `function mir(p, s) = [s*p[0], p[1], p[2]];` 헬퍼로
    `orient(mir(top,s), mir(bot,s))`처럼 양끝점 모두 미러링.
- 진법(0.1.2 갱신): 이 검사는 이제 validate.py 5계층의 **대칭성 프로브가 자동화**한다(함정 15). 수동으로는 `part`와 `mirror([1,0,0]) part`의 차집합 부피가 ~0인지 확인.

## 11. 절단(컷) 큐브는 대상 두께 전체를 넘어 관통시켜라

- 증상: 플로어의 디프 터널 컷 후에도 디프가 플로어와 155cm³씩 교집합.
  컷 큐브를 `translate([.., slab_z0-2]) cube([.., .., t+4], center=true)`로
  놓아 z범위가 slab 하단부만 덮음 — **slab 상단 8mm가 안 잘렸다.**
- 원인: 함정 2(center)의 컷 버전. center=true면 큐브 중심 기준으로 자라므로
  "아래에서 조금 올라오게" 배치하면 윗면이 slab 안에서 끝난다.
- 해결: 컷은 항상 `center=true` + 중심을 slab 중심(slab_z0+t/2)에 두고
  길이는 t+8처럼 **양측 돌출**. "살짝 겹치게"는 금물, 완전 관통이 원칙.

## 12. `offset(r)`은 도형을 r만큼 바깥으로 키운다

- 증상: 발판(foot)끼리 설계상 5mm 간격인데 33cm³ 교집합. bbox가 두 발판
  경계를 정확히 10mm씩 넘어 있었음.
- 원인: `linear_extrude(t) offset(r=w/8) square([w,w])` — offset은 모서리
  라운딩용이 아니라 **외 팽창**. 실제 발판은 w + 2·(w/8) 크기가 된다.
- 해결: 인접 구조물과의 간격 계산에는 팽창분 포함. 라운드만 원하면
  `offset(r) offset(delta=-r)` 쌍(안쪽으로 되돌리기)을 쓸 것.

## 13. Y축 방향 실린더의 회전 부호

- 증상: 디프 노즈 실린더가 터널 밖으로 35mm 노출(좌우 대칭 2곳, 각 8cm³).
- 원인: `rotate([90,0,0])`은 +Z를 **−Y**로 보낸다. +Y로 뻗으려면
  `rotate([-90,0,0])`. Rx(90): Y→Z, Z→−Y라는 한 줄을 매번 재확인하자.
- 해결: 방향이 햇갈리면 배치 직후 1회 렌더로 확인. 컷·터널 등 수용 구조의
  y범위도 함께 산출(노즈가 터널 끝을 넘는지 수치로 대조).
- 파생(F1, 0.1.4): 2D 폴리곤→YZ 매핑 검증값 — `rotate([90,0,-90])`은
  2D x→−Y(LE가 +Y 전방, 윙용), `rotate([90,0,90])`은 2D x→+Y(핀용),
  공히 2D y→+Z. 핀 회전 누락 사고는 부품 bbox 폭(132mm = 핀이 차체 옆에
  누움)으로 즉시 드러났다.

## 14. "안 겹침" 검증은 뜬 부품을 통과시킨다 — 결합면 접촉 검사

- 증상(실측 사례, 전부 간섭 0mm³ 검증 통과 상태):
  - 1:1 버기 휠 5개가 서스펜션에서 부유(전륜 19.2mm·후륜 9.2mm) — 허브에
    림 안면이 닿을 시트 플랜지가 없었다. 연결성 검사에서 "휠 5개 = 부유 섬"으로 드러남.
  - 위시본 부싱이 브래킷에 안 끼워져 11mm 부유 + 축이 X(아웃보드)라 운동학적으로도
    틀림(A암 스윙축은 Y). 우연히 가까운 다른 부품(쇼크-타워 6.1mm)이 쌍 최단거리로
    측정되어 "붙어 있음"으로 오판할 뻔한 케이스.
  - RC 예제 보닛이 섀시에서 4.0mm 부유(마운트 탭 자체가 없음).
  - 스페어 타이어가 스탠드오프에서 3.4mm 부유.
- 원인: 간섭 검사는 교집합만 본다. 뜬 부품은 교집합 0 = PASS. 접촉은 별도 명세로
  검증해야 한다.
- 해결: validate.py 5계층(0.1.2) — `CONTACT = [(A, B, 최대허용간극), ...]` 명세의
  실측 최단 간극 검사 + 접촉 그래프 연결성 검사. **결합면을 새로 만들면
  CONTACT에도 반드시 추가.** 부싱 설계 패턴: 축=스윙축(Y), 양측 플랭크 판이
  0.4mm 간극으로 클램프, 아암은 판 밖에서 시작(판 사이 통과 시 관통 간섭).
  허브-휠 패턴: 허브에 Ø(림 시트 직경) 플랜지를 내밀어 림 안면과 0.4mm 시트.
- 파생: 서브어셈블리(판+빔 등 뭉친 그룹)는 나머지 부품과 **용접 1본만** 연결되면
  충분 — 부품 내부 용접은 무한정 공짜이므로, 지지 구조 때문에 부싱·아암과
  엉키면 지지를 1본으로 단순화하는 게 충돌 해결의 지름길이었다.

## 15. 대칭성 프로브 — 미러 누락의 자동 탐지 (invert 함정 포함)

- 증상: 같은 버그류가 한 프로젝트에서 3회 — ① 좌측 코일오버 부재 ② 좌측 타워
  슬롯 미절단(좌측 타워가 바디 관통 50.8cm³) ③ 좌측 펜더 전체 부유(렌더
  육안으로만 발견). 전부 간섭·접촉 검사를 우연히 통과함(우측만 온전하면 쌍
  검사는 성립).
- 해결: 부품 메시를 x-미러한 본과 불리언 교집합 → `차집합비 = 1 − 교집합/부피`
  ≤2%면 대칭. validate.py 5계층에 내장(함정 10의 수동 권고를 자동화).
- 함정: trimesh는 `apply_transform`에서 **음의 행렬식이면 와인딩을 자동
  교정**한다. 여기에 `mesh.invert()`까지 하면 와인딩이 다시 뒤집혀 manifold
  부피가 음수 → 전 부품이 ~200% 비대칭으로 오판. 미러 후 invert 금지.

## 16. 캡슐(로드)의 근접 판정은 표면 거리로, 중심선이 아니라

- 증상: 어퍼암 로드가 플랭크 판 모서리를 스침(~3cm³). "중심선이 판에서 30mm
  떨어졌다"고 손계산해 안심했는데 r15 캡슐 표면이 판 모서리(코너)에 닿고 있었음.
- 원인: rod()는 hull-sphere 캡슐 — 반지름이 크고 비스듬히 지나갈수록 중심선
  거리와 표면 거리의 차가 커진다. 특히 상자의 **모서리**가 코너케이스.
- 해결: 손계산은 "세그먼트-점/세그먼트-상자 최단거리 + 양쪽 반지름"으로 할 것.
  검증은 min_gap(정점→표면 양방향 프로브)이 잡아주므로, 설계 시점의 대략 계산과
  검증 결과가 다르면 무조건 검증을 믿고 좌표를 찍어볼 것.

## 17. 캡슐 암(로드)의 종단점은 스텁 팁 평면 바깥에

- 증상(F1 1:14): 서스펜션 암 3본의 끝 구를 "스텁 축에서 반경 R스텁+R로드+간극
  (4.65mm)"에 배치했는데 양측 휠에서 동일하게 3.9mm³ 관통. 교집합 bbox가 스텁
  팁(x=34) 정면 x[34.0,36.4]에 정확히 위치 — 끝 구가 아니라 그 직전이 범인.
- 원인: 끝 구이 축 반경을 지켜도, 비스듬히 접근하는 **샤프트(선분)가 스텁
  x구간에 진입한 직후 축에 더 가까워진다**. 종단점을 스텁 구간 안쪽(x=36)에
  두면 팁 직전 크로스섹션 중심이 반경 ~3.5까지 밀려 들어온다(허용 4.5 미만).
  함정 3(끝단 뻗음)·16(표면 거리)의 확장판.
- 해결: 종단점 x를 스텁 팁 평면 바깥(= 스텁 x구간이 시작되는 좌표)에 두면
  샤프트가 스텁 구간에 아예 진입하지 못하고 끝 구만 접촉(실측 간극 0.09mm).
  "끝점-축 반경"과 "샤프트 선분-축 거리"는 별개로 계산할 것.

## 18. 원통(휠) 옆에 부품을 놓을 땐 최전방이 아니라 점유원으로

- 증상(F1 1:14): 프런트 윙 플랩을 "타이어 앞코 Y≈152.5"만 피해 배치했는데
  타이어와 1,024mm³. 교집합 두 성분이 x[40.2,63.8](타이어 폭 전체) ×
  y[132.8,149.2] × z[12.9,22.3] — 플랩 후행부가 타이어 측면 원판에 박힘.
- 원인: 원통의 점유영역은 x대역 전체에서 **(y−ay)²+(z−az)² < (r+여유)² 의
  원 내부**. 저z(z 8~20)에서는 Y 107~151이 거의 전부 원 안 — "앞코"는 원의
  한 점일 뿐이므로 피해 봤자 소용없다. 2차 사고: 원 판정 부등호를 반대로
  읽어 "23.45 < 25.5 → clear 2"로 오판(23.45 < 25.5는 원 **내부** = 충돌).
- 해결: 윙·빔·암 등 원통 근처 요소는 요소의 모든 코너점을 점유원식으로
  검사. 원 내부에 들어가는 저z 후행부는 실차처럼 휠 인보드로 스팬 분할
  테이퍼하거나 상방 재배치. 실차 프런트 윙 플랩이 휠 안쪽으로 짧아지는
  이유가 바로 이 점유원 규칙이다.

## 19. 미러 루프의 음수 폭 큐브 = 조용한 요소 소실

- 증상(F1 1:14): 프런트 윙 플랩을 `for (s=[-1,1]) wing_el(..., s*x0, s*x1, ...)`
  패턴으로 그렸는데 **좌측 플랩 2종이 통째로 없었다.** 에러·경고 전무.
  간섭·접촉·연결성 검사 전부 통과(우측만 온전하면 쌍 검사는 성립).
- 원인: 스팬 컷 큐브를 `cube([x1-x0, ...])`로 만들었는데 s=−1에서
  x1−x0 = −59.5 → **음수 치수 큐브는 에러 없이 빈 도형**. intersection이
  통째로 사라져 좌측 플랩만 소실.
- 해결: 폭을 abs()로 때우지 말고 `xa=min(x0,x1), xb=max(x0,x1)`로 정규화.
  음수 치수가 조용히 무시되는 특성상 이류 결함의 유일한 그물은 validate.py
  5계층의 대칭 프로브(본 사고는 17.3% 비대칭으로 포착).

## 20. loft 단면은 얇은 슬래브 — 실린더/구 섹션은 Z축소·Y팽창

- 증상(F1 1:14, 계통 오차): "접촉 간극 0.2 설계 → 2.99 실측"이 플로어·모노코크·
  노우즈·엔진커버 접합면 전체에서 반복. 윙-노우즈도 1.2mm씩 벌어짐. 게다가
  접합면끼리 4.0mm³(정확히 20×10×0.02) 교집합.
- 원인: 단면을 `cylinder(r=r)`로 구성하면 hull이 캡 포함으로 **Z로는
  z0+r..z1−r로 축소되고 Y로는 중심 양옆 ±r 팽창**. 섹션 좌표 자체가 거짓말을
  해서 모든 접합 설계값이 어긋난다. 슬래브(0.02)로 고치자 이번엔 두 부품이
  공유하는 접합면(Y=동일값)에서 슬래브끼리 겹침.
- 해결: 단면 = `translate([-hw, y, z0]) cube([2*hw, 0.02, z1-z0])`. 단,
  슬래브는 **전방 전용(y..y+0.02)**으로 놓고, 두 부품이 맞붙는 접합 섹션
  값에는 0.15 오프셋을 준다(양쪽 슬래브가 같은 평면을 두 번 차지하지 않게).
