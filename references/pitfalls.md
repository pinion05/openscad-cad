# OpenSCAD 실전 함정 카탈로그

RC 버기(12부품 조립 모델) 제작 중 실제로 발생했던 사고와 진단·해결 경로.
의심될 때마다 여기서 대조한다.

## 1. `use`는 변수를 가져오지 않는다 (최대 사고)

- 증상: 리어 휠 STL이 50mm 폭이어야 하는데 34mm짜리 이상 형상. 조립 파일의 휠
  위치 변수도 undef. **렌더만 봐서는 그럴듯하게 나와 발견이 늦었다.**
- 원인: `use <file>`은 모듈/함수만 import. 파일 최상위 `include <params.scad>`가
  없으면 그 파일 스코프의 변수 전부가 undef. undef는 치수가 0/이상값으로
  조용히 붕괴한다.
- 해결: 부품 파일·조립 파일 모두 `include <params.scad>` 직접 명시.
  빌드 스크립트는 stderr을 버리지 않고 `build_warnings.log`로 남겨
  "Ignoring unknown variable" 경고가 보이게 한다.
- 파생 규칙: 검증 스크립트의 부피/바운딩박스 리포트로 "의도 치수 ≠ 실측"을
  상시 대조한다 (bbox 이상 = 변수 붕괴 신호).

## 2. 실린더 `center=true` 누락

- 증상: 림 배럴의 내경 보어가 인보드 쪽 반만 솔리드로 막힘 → 너클·스텁액슬과
  5,400mm³ 교집합.
- 원인: `translate([0,0,-1]) cylinder(r=..., h=...)` — center가 없으면 z=-1에서
  위로만 자람. 대칭 보어 컷이었는데 한쪽만 잘렸던 것.
- 해결: `cylinder(..., center=true)` + 길이 여유. 배럴 컷은 h=barrel_len+4로
  양끝 돌출.
- 진법(진단 테크닉): ① trimesh `mesh.contains()`로 보어 내부 점 프로브
   (rtree 필요) ② 부품을 프리미티브별로 분리 익스포트해 범인 특정
   ③ 교집합 정점의 좌표값 히스토그램 — 파라미터 값(-2.5, 0, 2.5, 6...)이
   그대로 보여 어느 프리미티브인지 역추적 가능.

## 3. 캡슐(hull-sphere) 튜브 끝단

- 증상: "0.4mm 클리어런스"로 설계한 스포일러 스트럿 하단이 리어 패널에 3mm 가량 파고듦.
- 원인: `rod()` = hull of spheres. 끝점에서 od/2 만큼 더 뻗는다. 실린더 기준으로
  클리어런스를 계산하면 안전거리가 반지름만큼 부족.
- 해결: 부품 경계을 넘는 튜브는 끝점을 반지름만큼 더 띄우거나, 끝 몇 mm를
  평평한 실린더로 마감.

## 4. orient() 회전 순서

- 증상: 이 헬퍼를 쓰는 쇼크업소버 전부가 일관되게 엉뚱한 방향 → 휠·패널 대형 간섭.
- 원인: ẑ→v̂ 매핑은 Rz(φ)·Ry(θ) 순서(외부 Z, 내부 Y). Y를 밖에 두면 회전축이
  이동하지 않아 결과가 항상 XZ 평면에 갇힘.
- 해결: SKILL.md의 검증된 스니펫 사용. 방향 헬퍼는 비대칭 마커(한쪽만 큐브 붙이기)로
  렌더해 방향을 눈으로 확인하고 커밋할 것.

## 5. `-D` 오버라이드의 한계

- 시도한 것: ① 파일에서 할당된 변수를 -D로 덮지기(무효 — 파일 할당이 이김)
  ② 미할당 sentinel(`fn_override`) + `is_undef()` 삼항(루트에선 되지만
  include 실행 시점과 어긋남) ③ wrapper 파일에서 include 전 선할당
  (동작은 하나 `use`된 파일 스코프까지는 전파 안 됨).
- 결론: 전역 해상도 스위치가 필요하면 호출마다 명시적 `$fn=` 인자를 피하고
  루트 `$fn` 하나로만 통제. 안 되면 풀해상도로 익스포트하고 파일 크기로 타협
  (14만 삼각형 조립 STEP = 24MB, 수용 가능).

## 6. 음수 길이 파라미터

- 증상: `plate(60, y1-y0)`에 y1<y0 (뒤<앞 네이밍) → hull이라 에러 없이 동작하지만
  코너 계산이 뒤집혀 실제 폭이 의도보다 4mm 큼 → V브레이스와 충돌.
- 해결: 파라미터를 `yf/yr`(앞/뒤)로 명명하고 길이는 항상 양수 조합
  (`abs()`는 증상 은폐일 뿐).

## 7. 카메라/뷰 형식

- 6값 eye/center 형식 + `--projection=p` + 명시적 거리가 안정적.
- `--viewall`은 eye/center와 조합되며 방향을 예상과 다르게 재조정할 수 있고,
  gimbal 형식(translate+rot+dist 7값)은 프리셋 회전값(GUI: Top=(0,0,0),
  Front=(90,0,0), Right=(90,0,270), Diagonal=(55,0,25))과 짝이 맞음.
- 부품 단독 렌더는 `--autocenter --viewall --camera=0,0,0,60,0,30,0`로 충분.
- 투시 뷰는 착시가 심하다(측면도를 3/4뷰로 오독한 사례). 방향이 중요하면
  eye/center를 코드로 박아둘 것.

## 8. Python 라이브러리 버전/API

- trimesh: `contains()`→rtree, `split()`→scipy+networkx 필요. 없으면 그 기능에서만 죽음.
- cadquery 2.8: `importers.importStl` 제거됨. STL→STEP은 OCP 직접
  (`RWStl.ReadFile_s`, `tri.Node(i)`, `tri.Triangle(i).Get()`,
  `BRepBuilderAPI_MakePolygon/MakeFace`, `STEPControl_Writer`).
- 스크립트 작성 전 `dir(모듈)`로 실제 API 10초 확인이 문서 기억보다 빠르다.
- manifold3d `Manifold`에는 `.bounds`가 없다(`.bounding_box()`). trimesh와
  섞어 쓰는 진단 스크립트에서 bbox 프리필터를 걸 때 AttributeError로 조용히
  죽지 않게 할 것.

## 9. 운영: 공유 워크스페이스

- 세션 중 같은 디렉터리에 다른 에이전트의 병렬 산출물이 생길 수 있다.
- 내 산출물과 경로 분리(고유 접두사/하위 디렉터리) + 커밋은 화이트리스트 복사로.
  상대방 파일을 gitignore로 가리는 것보다, 레포를 새 디렉터리에 원하는 파일만
  복사해 만드는 것이 안전하다.

## 10. 미러 루프(`for s=[-1,1]`) 안의 X축 실린더·포인트 좌표

- 증상(1:1 버기): ① 좌측 허브 스터브가 차체 **안쪽**으로 뻗어 하프샤프트를
  관통(329cm³, bbox 220×60×60이 액슬 높이 중앙에 정확히 나타남) ② 좌측
  코일오버가 **아예 없고** 좌측 쇼크 타워 슬롯도 안 잘려 후드를 뚫음(50.8cm³).
- 원인: X축 실린더를 `translate([s*x0,...]) rotate([0,90,0]) cylinder(h=L)`로
  그리면 s=−1에서 시작점만 미러링될 뿐 **뻗는 방향은 항상 +X** → 좌측 부품은
  차체 중앙으로 자람. 마찬가지로 루프 안에서 축 좌표(쇼크 상하점)를 상수로
  쓰면 두 번 루프가 같은(+x) 위치에 그린다.
- 해결:
  - 실린더: `rotate([0, s*90, 0])` — 방향까지 s에 비례.
  - 점 기반 도형: `function mir(p, s) = [s*p[0], p[1], p[2]];` 헬퍼로
    `orient(mir(top,s), mir(bot,s))`처럼 양끝점 모두 미러링.
- 진법: **validate.py는 충돌은 잡지만 "그려지지 않은 부품"은 못 잡는다.**
  좌우 대칭 부품은 `part`와 `mirror([1,0,0]) part`의 차집합 부피가 ~0인지,
  또는 bbox가 x축 대칭인지 한 줄 프로브로 확인할 것. 무증상 결함의 주 원인.

## 11. 절단(컷) 큐브는 대상 두께 전체를 넘어 관통시켜라

- 증상: 플로어의 디프 터널 컷 후에도 디프가 플로어와 155cm³씩 교집합.
  컷 큐브를 `translate([.., slab_z0-2]) cube([.., .., t+4], center=true)`로
  놓아 z범위가 slab 하단부만 덮음 — **slab 상단 8mm가 안 잘렸다.**
- 원인: 함정 2(center)의 컷 버전. center=true면 큐브 중심 기준으로 자라므로
  "아래에서 조금 올라오게" 배치하면 윗면이 slab 안에서 끝난다.
- 해결: 컷은 항상 `center=true` + 중심을 slab 중심(slab_z0+t/2)에 두고
  길이는 t+8처럼 **양측 돌출**. "살짝 겹치게"는 금물, 완전 관통이 원칙.

## 12. `offset(r)`은 도형을 r만큼 바깥으로 키운다

- 증상: 발판(foot)끼리 설계상 5mm 간격인데 33cm³ 교집합. bbox가 두 발판
  경계를 정확히 10mm씩 넘어 있었음.
- 원인: `linear_extrude(t) offset(r=w/8) square([w,w])` — offset은 모서리
  라운딩용이 아니라 **외 팽창**. 실제 발판은 w + 2·(w/8) 크기가 된다.
- 해결: 인접 구조물과의 간격 계산에는 팽창분 포함. 라운드만 원하면
  `offset(r) offset(delta=-r)` 쌍(안쪽으로 되돌리기)을 쓸 것.

## 13. Y축 방향 실린더의 회전 부호

- 증상: 디프 노즈 실린더가 터널 밖으로 35mm 노출(좌우 대칭 2곳, 각 8cm³).
- 원인: `rotate([90,0,0])`은 +Z를 **−Y**로 보낸다. +Y로 뻗으려면
  `rotate([-90,0,0])`. Rx(90): Y→Z, Z→−Y라는 한 줄을 매번 재확인하자.
- 해결: 방향이 햇갈리면 배치 직후 1회 렌더로 확인. 컷·터널 등 수용 구조의
  y범위도 함께 산출(노즈가 터널 끝을 넘는지 수치로 대조).
